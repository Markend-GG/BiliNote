## R1 本地视频播放 + 时间点跳转

**需求**：无论本地视频还是在线视频，最终都下载到本地；浏览器打开笔记时能直接定位到本地视频并**在浏览器内播放**；点击「原片（mm:ss）」时间点 → 跳到本地视频对应时间播放。

**现状**：在线视频本地副本已存在 `data/data/{video_id}.mp4|.mp3`；本地上传源文件在 `uploads` 卷。缺：① 支持 HTTP Range 的流式播放接口（`<video>` seek 必需 206）；② 前端「原片跳转」目前打开 B 站外链，「原文参照」dock 只显示文本时间轴。

**设计要点（未定稿）**：
- 后端：`GET /api/media/...` 流式接口（Range/206、按扩展名 Content-Type），按 task_id/video_id 解析真实文件；路径安全（uuid 校验 + 根目录白名单）。
- 前端：内嵌 `<video>/<audio>` 播放器（「原文参照」dock 加播放器 tab 或独立侧栏）；时间胶囊点击 → 打开播放器并 `currentTime = t`；复用 V3.3 的时间胶囊解析。
- 待拍板：胶囊行为「本地播放替换 B 站外链」还是「本地优先 + 外链兜底」；纯音频用 audio 播放器；是否转码降码率。
- 磁盘策略：`data/data` 与 `uploads` 的媒体文件目前无清理策略，需一并设计。

## R2 课件 + 视频 + 课后练习（多素材任务）

**需求**：一次生成可上传**课件 + 视频 + 课后练习**，用多素材联合优化笔记。

- **课后练习（2026-11-01 补充）**：要「运用课程中的思路对课后练习生成对应方式的解答」——不只匹配引用，还要按课里讲的方法产出解答。

**现状**：任务模型是单一 `video_url` + 单风格；上传控件单文件（`accept='video/*'`，拖拽不校验类型）。

**设计考虑（初步）**：
- 数据模型：任务素材表（`material`：role=video/slides/exercises + 文件 + 解析产物），form_data 扩展；新建表单改多文件（每项标类型）。
- 课件（PPTX/PDF）：文本抽取（python-pptx / PyMuPDF）+ 每页转图 → 走现有多模态读图链路；笔记中可用「[课件 P12]」式引用；视频-课件时间对齐是难点，建议先做语义关联。
- 练习：提取题干 → 与视频讲授内容匹配 → 例题精讲引用练习编号，并按课程思路生成解答；图片题走多模态。
- 提示词：新增"素材感知"章节；注意历史教训——给风格提示词加规则要防正文被压缩。
- 分期建议：P1 多文件上传 + 课件文本/图入 prompt；P2 练习匹配与解答；P3 视频-课件时间对齐。
- 存储：走 uploads 卷；课件转图进 static 或独立目录，清理策略与截图孤儿清理对齐。
- **2026-11-01 补充**：**不局限在本项目内**——允许用外部工具组合完成多素材分析与练习解答（如导出到 IMA、WorkBuddy 等处理）；本项目内实现只是选项之一。

## R3 导出 Obsidian

**需求**：把笔记导出成 **Obsidian 可直接使用的格式**（具体清单待定：Markdown + 图片附件、frontmatter/标签/双链、Canvas 等）。

**现状**：已有「导出离线 HTML」与打印，没有 Markdown 导出。笔记本体是 Markdown + 截图 URL。

**设计要点（未定稿）**：导出 zip（`.md` + `assets/` 相对引用）；`#heading` 锚点 Obsidian 天然兼容；frontmatter/标签可选；文件名/文件夹按笔记或文件夹分组。

## R4 学习模式

**需求**：打开学习模式后可**呼出视频在页面内观看**；**进度条上标注章节定位点**；视频**下方章节卡片显示章节名称 + 简介**；点卡片/定位点跳到对应时间。

**关联**：播放能力依赖 R1；章节数据可复用现有章节导航（OutlineNav）与正文时间胶囊；"章节简介"为新数据（可由该章节笔记内容/AI 生成摘要）。

**设计要点（未定稿）**：chapters 元数据 `[{start, end, title, summary}]`；进度条叠加章节段；布局为学习模式全屏/分栏（播放器 + 笔记）；纯音频用 audio 版。

**2026-11-01 补充**：在线视频（如 B 站）**直接播放平台在线视频**（iframe 嵌入官方播放器）**也可以**，播放**本地下载副本**同样可接受——两种皆可，定稿时决定（可并存：在线优先 + 本地兜底，或按设置切换；权衡 B 站 iframe 的登录/清晰度/版权限制与本地副本的磁盘占用）。

## R5 沉浸式笔记（AI 定制的网页版）

**需求**：AI 为每条笔记"量身设计"一个网页版，浏览器直接打开。

**现状**：已有通用样式的「导出离线 HTML」；此需求是 AI 按笔记内容做**个性化版式/视觉**。

**设计要点（未定稿）**：
- 方案 A：AI 直接生成 HTML/CSS（灵活，但**有 XSS/脚本风险**，需 sanitize 或沙箱 iframe）。
- 方案 B：AI 输出布局描述（JSON/DSL）由固定渲染器渲染（可控、安全，建议优先）。
- 产物可预览 + 导出为独立 html 文件。

## R6 视频合集批量任务

**需求**：一次性把 **B 站合集 / 收藏夹 / UP 主**下的所有视频添加成任务、批量生成笔记。

**现状**：单任务单视频；已有分 P 支持；有 (video_id, style) 防重与默认 3 worker 并发；B 站下载仍可能被风控（412）。

**设计要点（未定稿）**：yt-dlp 枚举合集/收藏夹/UP 主列表（分页、去重）；批量建任务 + 进度面板（成功/失败/跳过）；并发与限速控制；失败重试策略；自动归档文件夹；**磁盘策略必须先定**（每集约 450MB，60 集 ≈ 27GB）。

## R7 跨笔记 AI 问答

**需求**：问答时在**多篇笔记**范围内检索并回答。

**现状**：ChromaDB 每任务一个 collection，问答只查当前笔记；此前因需重构索引而搁置，现明确提为需求。

**设计要点（未定稿）**：统一 collection + metadata（task_id/source）过滤；或"先路由选笔记 → 再检索"两段式；答案带来源引用（笔记标题 + 章节 + 时间点）；与现有全文 FTS5 互补（语义 + 关键词混合检索）。

**2026-11-01 补充**：**不局限在本项目内**——导出笔记后在 **Obsidian**（配合插件）、**IMA**、**WorkBuddy** 等外部工具完成跨笔记问答同样可接受；本项目内建跨篇检索只是可选路线之一。定稿时先确认"能力优先（外部落地）还是内建优先"。
